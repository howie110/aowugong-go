# VPN 公共分流规则设计

## 目标

为 VPN 资源分配功能增加一份全局、唯一、由文件维护的公共分流规则。Clash、Surge、Shadowrocket 订阅将把这份规则合并进配置；v2rayN 继续返回标准节点订阅。由于 v2rayN 的标准节点订阅本身不能携带完整路由配置，用户页面不再提供独立的规则资源；旧的 `routing` 响应仅保留给历史链接兼容。

工作台「资源分享 > VPN 分配」页面只读展示规则原文，供管理员查看。规则不进入数据库，不提供页面编辑、草稿、发布、版本、回滚或多份并存。

## 范围与非目标

包含：

- 从 `storage/private/vpn/common-routing.json` 读取唯一公共规则文件。
- 用严格 JSON 校验规则，并在每次订阅生成时读取最新内容。
- 将 Xray routing 规则映射到 Clash、Surge、Shadowrocket 的规则段。
- v2rayN 保持标准节点订阅，不在用户资源页提供独立规则资源；兼容已生成的旧 `routing` 地址。
- 在管理员 VPN 分配页只读显示规则文件的多行原文。
- 规则文件不存在时保持现有订阅兼容行为，视为没有公共规则。

不包含：

- 数据库迁移、规则版本表、审核流程或页面保存接口。
- 修改节点来源文件的内容或把节点凭据写入浏览器。
- 为不同用户维护不同规则；所有用户和资源使用同一份最新公共规则。
- 改变现有用户订阅 Token、轮换、撤销和权限模型。

## 公共规则文件格式

文件是 Xray routing 对象的 JSON 文本，示例结构如下：

```json
{
  "domainStrategy": "IPIfNonMatch",
  "rules": [
    {
      "type": "field",
      "domain": ["geosite:cn"],
      "outboundTag": "direct"
    },
    {
      "type": "field",
      "ip": ["geoip:private"],
      "outboundTag": "direct"
    }
  ]
}
```

实现沿用当前 Xray 配置使用的 `domainStrategy`、`rules`、`type`、`domain`、`ip`、`port`、`network`、`protocol` 和 `outboundTag` 字段。规则目标统一约定为：`proxy` 表示代理组，`direct` 表示直连，`block` 表示拒绝。未知或无法转换到目标客户端的规则不静默丢弃，而是在生成订阅时返回明确错误。

文件继续属于私有存储，不提交节点或规则正文到公开 Git 仓库。页面展示接口只对管理员返回规则原文；普通用户摘要不返回该字段。

## 架构与数据流

### 文件读取

`SourceCatalog` 负责读取 `common-routing.json`，限制文件大小与当前私有配置相同。`Build(profileCode)` 每次调用都重新读取公共规则文件，因此管理员通过 AI 修改并部署文件后，用户下一次刷新订阅即可拿到最新规则，不需要数据库发布动作。

缺少规则文件或文件为空时，构建器使用现有的客户端配置和兜底规则。文件存在但 JSON 无效、规则字段不支持或目标格式无法转换时，构建失败并返回错误，避免用户得到半套规则。

### 四种客户端输出

- Clash：保留节点和代理组，替换配置中的 `rules` 为公共规则转换结果；缺失原生 Clash 文件时，沿用现有 VMess 自动生成逻辑并写入公共规则。
- Surge：保留节点和代理组，替换 `[Rule]` 段为公共规则转换结果；缺失原生 Surge 文件时，沿用现有自动生成逻辑并写入公共规则。
- Shadowrocket：保留原生配置的其他段落，替换或创建 `[Rule]` 段，使用同一组转换后的规则。
- v2rayN：`v2ray` 继续返回标准 Base64 分享链接节点订阅。公共规则不会伪装成 v2rayN 节点订阅；旧的 `routing` 配置响应继续由服务端兼容，但新摘要和用户页面不再生成或展示其地址。

规则目标映射使用当前配置中的代理组/策略名：`direct` 映射为 `DIRECT`，`block` 映射为 `REJECT`，`proxy` 映射为统一的 `PROXY` 选择组；生成的配置保证 `PROXY` 组存在，原生配置则优先复用已有同名组，无法确定时使用该资源的首个代理组。

### 页面与接口

服务端摘要增加只读的 `common_routing` 信息，包含文件名和原文。管理员分配页面增加一个多行只读文本区和“复制规则”入口，不提供输入框、保存按钮或任何规则生命周期操作。

公开订阅路由继续使用现有设备 Token。格式参数 `routing` 和 JSON 响应仅为历史链接兼容；普通四种客户端的地址生成规则不变，新的用户摘要不再返回独立规则地址。

### 安全与兼容性

- 规则文件只从 `SourceCatalog` 配置目录的直接子文件读取，禁止路径穿越。
- 规则正文不得写入日志、数据库或分发器以外的外部系统。
- 现有订阅 URL、Token 版本、管理员权限和普通用户资源隔离保持不变。
- 公共规则读取失败会阻止新的订阅生成和重新发布，但不影响已生成的数据库记录或撤销流程。

## 测试策略

- 单元测试覆盖规则 JSON 解析、空文件兼容、域名/IP/端口规则转换、目标映射和不支持规则的错误。
- SourceCatalog 测试验证同一公共规则会进入 Clash、Surge、Shadowrocket 输出，并保留旧 v2rayN `routing` 配置兼容。
- Service 测试验证四种订阅地址不泄露独立 `routing_url`，且历史 `routing` 请求仍返回最新磁盘内容。
- HTTP 测试验证管理员摘要能看到规则原文，普通用户摘要不泄露规则字段，并验证公开 `routing` 响应的类型和内容。
- 前端测试/构建验证管理员页面是只读展示，用户页面不展示独立 v2rayN 规则资源，现有节点链接复制和二维码流程不回归。
